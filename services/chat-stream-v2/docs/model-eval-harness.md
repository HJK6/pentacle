# Model evaluation harness

This offline harness replays frozen retained engineering tasks in disposable Git worktrees. It changes no live routing or production state. Raw tasks, transcripts and bundles stay outside the source repository.

The Terra trial uses `terra-high` (`gpt-6.1-terra`/high), `terra-xhigh` (same model/xhigh), and `sol-medium` (`gpt-6.1-sol`/medium). `runner.ARMS` schedules those three; dispatch and usage parsing use provider identity. Legacy Luna/Haiku bindings remain for old self-tests and historical replay only. The Terra trial starts no Claude process.

Run commands from `services/chat-stream-v2/tools`: `python3 -m model_eval.cli freeze /abs/tasks.json`; `python3 -m model_eval.cli eligibility --repo /abs/repo --pre-fix SHA --fix SHA --cmd COMMAND --red-pattern REGEX --test-files PATH --out /abs/receipts`; `python3 -m model_eval.cli run --tasks /abs/tasks.json --bundle /abs/bundle` (optional `--task ID`, `--model ARM`, `--timeout SECONDS`). Every path used by a model must be absolute. Runs already represented in runs.jsonl, including failures, are skipped on resume.

Task fields: id, class, repo, sha, brief, known. Fix tasks add fix_sha, test_files, score_cmd; tests are restored from fix_sha before replay and before scoring. QA known.verdict is accept or reject. Boundary tasks write diagnosis.json; known.diagnosis defines exact root_cause, ordered causal_chain, product_or_harness and discriminating_control values. Missing, malformed or mismatching structured answers score zero; explanations are independently graded. Historical typed tasks use check_cmd. Optional setup_cmd runs after worktree creation. Per-arm pricing classes live in runner.MODELS; tasks.pricing supplies named API-equivalent rates.

Each Codex process reads its prompt from stdin with explicit model/effort/cwd. A fake agent-orch first on PATH records START, END and canonical-schema report calls without contacting the daemon. Blank TMPDIR is normalized for portable subprocess startup. No-report, crash and timeout cells remain failed rows with zero scores and observed usage; absent usage is unavailable. The CLI does not attest effective effort, which remains unavailable.

Each run directory contains the fake CLI log, stdout/stderr, last message, full source diff against the prepared tree, and record.json. runs.jsonl is the append-only frozen cell table. The standalone grade command uses a headless Sol/high option; the Terra trial instead commissions one independent Sol/high seat with only scrubbed, shuffled ABC packets. Failed outputs keep grade zero. grader.parse_grades requires every finished-output label. Frozen task prompts and rubrics must accompany the packet. Do not send the label-to-arm map to the blind reviewer.

Use scoring.terra_recommend on completed rows: select high if its correct and protocol totals meet Sol and its grade is at least Sol minus one; else test xhigh; else select neither. Fewer than two tasks or two finished rows per comparison is under-sampled. The comparison never promotes a model from the bench alone, and boundary results never promote row 3. No billing or statistical-significance claim follows from named API-equivalent weights.

The trial lead records budget checks before every admitted batch, freezes tasks.json and its SHA256 in the spec Results before scoring, and commissions independent final harness QA. Self-tests: `python -m pytest -c /dev/null -p no:cacheprovider services/chat-stream-v2/tools/model_eval/tests -q` from the repo root. Headless behavior, related QA samples, multiple-choice boundary answers, one run per cell and blind-grader provider bias remain limitations.
