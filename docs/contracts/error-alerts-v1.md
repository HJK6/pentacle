# Error Alerts v1

The executable schema is `error-alerts-v1.schema.json`; `error-alerts-v1.d.ts` supplies TypeScript shapes. `test/fixtures/error_alerts/responses.json` contains synthetic successful responses, errors and invalid requests, checked by `services/chat-stream-v2/tests/test_error_alerts_contract.py`. This contract is frozen for the separately owned panel. Examples are contract fixtures, not product acceptance evidence.

## Transport and response semantics

Use the existing authenticated WS/IPC owner. The renderer calls `window.cc.errorAlerts(verb, fields)` with one of the seven exact `error.*` verbs. The shared channel is `chat-stream:error-alerts`. The bridge adds `{ok:true}` to a successful wire response and returns `{ok:false,error_code,retry_after?,current_revision?}` on refusal or a disconnected transport (`error_code=disconnected`). The existing client owns request IDs; renderer fields exclude `type` and `request_id`. No extra connection. The capability is `snapshot.capabilities.error_alerts_v1`; absent capability means unsupported, with no report attempts. All operations require an actual, currently valid operator credential. Seat elevation is insufficient.

List defaults to `filter=all`, limit50; max100. Cursor is opaque, scoped to filters, ordering latest timestamp descending then stable source/id. No total-history claim. `id` matches the exact visible ID, native source ID or operation UUID. `received` means `delivery.state=delivered` with generation-bound proof. `partial=true` with fixed `errors` retains available rows and explicitly warns about missing sources; a wholly failed query is an error, never an empty result. Retain prior data with a stale indicator on disconnected/error refresh. Poll only while mounted at the existing dashboard cadence.

`error.get` is a read; explicit authenticated detail opening separately calls `error.mark` with `seen`. Ack is a deliberate second action. Marks affect typed attention only; read-only source projections return `read_only`. They never recover an operation, alter delivery or resolve a legacy question/consent. Legacy title is source presentation; original body is not exposed/copied by this API. No new global alert broadcasts.

Settings expose seven fixed family rows. Only voice is editable. `error.settings.set` requires family+expected_revision and at least one of delivery_mode/mute_for_s/restore_defaults. `mute_for_s=0` clears a temporary overlay; 900/3600/86400 starts an overlay from server time, preserving saved delivery_mode. Omitted fields retain values. `restore_defaults=true` is exclusive of mode/mute fields and sets immediate, no overlay. Empty updates and `restore_defaults=false` alone are invalid. Label persistent muted “Record only”. Revision conflict returns current_revision; reload, do not silently overwrite. Audit defaults20/max100, cursor for older entries. Limits and recipient are display only.

Report allows only the schema fields, frame <=4096 UTF-8 bytes. `voice_operation` is required to register a client-only upload-read failure; other reports refer to an existing principal-owned operation. Optional dropped_count is allowed only with code report_gap, which records incomplete coverage and never sends an immediate failure alert. Exact duplicate event IDs ACK idempotently; altered content conflicts. Client recovery is evidence, never server send proof. Report failure never blocks voice sending. Timers alone yield unknown/unconfirmed. Expected no_speech/too_long/unsupported/permission_declined/cancel remain quiet.

No row's `folded` status means delivered. Follow folded_into_notice_id to the digest's actual proof; original recipient and generation remain visible. Known legacy records without proof are legacy_unknown. Delivery attempts expose fixed safe codes, not arbitrary transport errors. Timestamps are nullable when unproved; do not infer them from UI refresh time.

## File ownership

Backend/integration lead owns `services/chat-stream-v2/**`, `services/_shared/notifications_store.py` and its tests, this contract and fixtures, `main/chat_stream_client.js`, `main/cc_handlers.js`, new `main/error_alerts_ipc_bridge.js`, their tests, `renderer/web_voice.js`, `renderer/voice_action_delivery.js`, `renderer/voice_answers_binding.js`, `renderer/question_voice_bar.js`, and new `renderer/error_reporting.js` with voice/reporting tests. The voice owner may add a required voice reporter script through the panel owner, without editing shared renderer entrypoints concurrently.

Separate web lead owns `renderer/dashboards/error-alerts.js`, `renderer/dashboards/registry.js`, relevant renderer shell navigation/bootstrap and styles, `renderer/index.html`, `renderer/web_cc.js`, `preload.js`, `scripts/build-web.js`, `test/e2e/error_alerts_gate.cjs` and panel/deep-link component tests. Web lead implements `cc.errorAlerts` as a thin adapter to the named shared channel. Backend supplies the shared channel and client implementation. Both leads coordinate new reporter script registration through the web owner. Panel owner can add scoped CSS rather than rewrite unrelated styles.

Backend gate owns the live isolated endpoint manifest `{url,credential_file,product_root,product_sha}` and invokes the UI runner while it is alive. UI runner must refuse missing/non-disposable credentials or non-loopback fixture targets. No private dashboard/catalog definitions. No mobile edits until explicit writer transfer. No work-lanes implementation.
